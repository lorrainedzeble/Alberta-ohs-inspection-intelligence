# Dashboard mockup: shapes considered, and why one won

Referenced from CLAUDE.md. Written down for the same reason `opportunity-framing.md` exists: the "converge on one" judgment behind this dashboard's form should be checkable by a stranger, not just implied by the finished HTML file.

## Criteria, locked before comparing shapes
1. Must map onto Dana's actual Monday-morning sequence (scan, confirm, rank, brief), not invent a new capability the skills don't have.
2. Must use the pinned Roofing gold example as a real, testable centerpiece, not a placeholder number.
3. Must be checkable against CLAUDE.md's spec: every panel must be fillable from real data already produced by this workspace's skills (`evaluation/quarterly-memo-2026-07-10.md`, `evaluation/use-log.md`, the `--all` scan output), never a panel invented because it looked good.
4. Must not misrepresent the boundary-tie finding: a deferred industry's shortlist must visually read as different from a validated one, not just carry a smaller caption.
5. Realistic to build and screenshot within the remaining time, as a static, self-contained HTML file (no server, no live database connection required for the deliverable).

## Shapes considered

**1. Triage queue (a card per industry, scannable in one pass).** All 15 confirmed industries as cards in a single scrollable list, each showing a verdict badge (validated / deferred / rejected), the fatality/trend flags that got it flagged in Step 1, and the back-test numbers. Optimized for "what should I even look at this week," the very first question in Dana's sequence. Strongest fit for criterion 1. Weak on depth: a card can't hold a full ranked shortlist without becoming a list-inside-a-list, criterion 4's requirement (visually distinguishing unambiguous from tied employers) would get cramped.

**2. Master-detail drill-down.** A left-hand industry list (with verdict badges) and a right-hand detail panel that fills in with the selected industry's full picture: trend numbers, back-test result, shortlist split into unambiguous/tied groups, employer briefs. Mirrors the memo's own structure almost exactly. Strongest fit for criteria 2-4: the gold example and the tie-split both get real, un-cramped room in the detail panel. Weaker on criterion 1 in isolation (a stranger lands on one industry at a time, not the full 15-industry scan), but the list panel is always visible alongside it, so the queue view isn't actually lost, just demoted to a sidebar instead of the whole screen.

**3. KPI-tile summary plus one flat sortable employer table.** Top row of stat tiles (302 scanned, 114 flagged, 6 validated, 9 deferred, 0 rejected), then one big table of every shortlisted employer across all 15 industries with sortable columns (industry, score, tie status, fatality flag). Optimized for cross-industry employer scanning ("show me every fatality-flagged employer regardless of industry"), a real but secondary use case Dana has not actually asked this workspace to support yet. Fails criterion 1 as the primary shape: it isn't how the confirmed sequence (scan industries, confirm, then drill into ranking) actually unfolds, and criterion 3 gets shaky, since a flat table inviting arbitrary re-sorting by an unconfirmed criterion risks presenting the workspace's own disclosed "favors higher volume" scoring bias as if it were a neutral sort option.

**4. Memo-as-HTML (render the existing markdown memo with collapsible sections, minimal added interactivity).** Lowest engineering risk, closest fidelity to the artifact that's already been checked and verified. Fails criterion 5's spirit even though it's the cheapest to build: it doesn't actually demonstrate the mockup-first discipline this exercise is for, it just reformats a document that already exists. Also weakest on usability, since a wall of collapsed sections is a worse "Monday morning" experience than a real list-plus-detail interface.

## Converged: shape 2, master-detail drill-down, with shape 1's queue folded in as the list panel

Shape 2 wins outright on criteria 2, 3, and 4, and shape 1's core value (the scannable queue) is preserved as the persistent left panel rather than lost. Shape 3's cross-industry table idea is not discarded, just deferred: it is a real, legitimate future feature (noted here so the omission is a decision, not an oversight) but is out of scope for this cycle's dashboard, since the workspace has never actually been asked to support ranking across industries in one flat list, only within a chosen industry, and building it now would be exposing a capability because it's easy, not because a real use case called for it, the same trap CLAUDE.md's refusals section already guards against elsewhere.

**Walking-skeleton discipline:** the dashboard is a real, single self-contained HTML file (`dashboard/index.html`) with the pinned Roofing 2020 gold example (`employer_count` 1137, `person_years_sum` 4907.7, `ltc_count` 133, `ltc_rate_per_100_person_years` 2.71, `di_count` 236, `di_rate_per_100_person_years` 4.809, `fatality_count` 1, `enforcement_action_count` 802) as the default-selected, literally-testable centerpiece: anyone opening the file lands on Roofing first and can check the displayed numbers against CLAUDE.md's pinned section by eye, with zero clicks. Everything else fills in with real data already produced and verified by this workspace's skills, not fabricated placeholder rows.

## Spec gap this mockup exposed, folded back into CLAUDE.md

Building the detail panel's tie-split view surfaced a real gap: CLAUDE.md's Skills section describes `inspection-target-ranking`'s output in prose but never states, as a rule a stranger building any presentation layer (this dashboard, or a future one) could check against, that a validated industry's shortlist can itself still contain a boundary tie below its confirmed top employers (Mechanical Contracting and Home Support Services, both cleanly validated at the gate level, both still have a tied slot further down their shortlist). This was previously only documented in `knowledge/data-cautions.md` and the memo, not in CLAUDE.md's own Skills description. Added a one-line cross-reference in CLAUDE.md's skill 2 description pointing a future reader to this fact, so a panel you cannot fill without going hunting through a use-log entry is treated as a real spec gap, not an acceptable state of affairs.

## Revision after the walking skeleton was reviewed (dated 2026.07.12)
The first built version (a plain text-table master-detail layout, criteria 2-4 satisfied but visually flat) was reviewed against real reference screenshots the analyst supplied of comparable compliance-monitoring dashboards, which were consistently chart-and-KPI-tile driven rather than table-driven: colored achievement percentages, donut charts for category splits, bar charts for comparative metrics, and filter dropdowns rather than a static list. This is exactly the "cold-read it, watch where they stall" discipline applied to a mockup instead of a document: the first build technically satisfied every locked criterion but didn't match what a reader actually expected a dashboard to look like.

Revised without changing any of the underlying data or the criteria: added a verdict-distribution donut chart and a back-test-lift bar chart (both computed from the same real numbers already in the walking skeleton, no new data needed), colored KPI tiles, industry/verdict filter dropdowns, and colored flag badges in place of plain "Yes/No" text. The master-detail structure, the boundary-tie split, and the pinned gold example as the default-landing centerpiece are all unchanged, since those were the parts the criteria actually required; only the visual form changed. Re-verified live in-browser after the revision: filters correctly re-render the detail panel, and the colored flag badges correctly show red for a real "Yes" case (Finning International's fatality and Acceptance/Approval-concern flags in Mobile Equipment Dealers).

## Second revision, a genuine rebuild rather than a polish pass (dated 2026.07.13)
The chart-and-tile revision above still fell short on direct review: no real navigation existed at all (one long scrolling page), the layout did not read as a professional BI tool, and there was nothing to click through as separate views. This is a different class of gap than the first revision's, that one was a visual-style mismatch on a structurally sound shape; this one meant the shape itself (a single undifferentiated page) was wrong once real interactivity and multiple chart types were required.

Rebuilt from the same real data (`dashboard_data_v3.json`, built from the same verified result files as before, with the Roofing gold example now carrying its full 2020 to 2024 `by_year` series instead of just 2020) into a genuine five tab structure with a fixed left sidebar: Overview, Industry scan, Back-test & verdicts, Employer shortlists, Gold example. Each tab is a real, separately rendered view, not a scroll anchor. Charts are hand built inline SVG, no external library dependency: a donut with real visible arced slices (`stroke-dasharray`-free, built as SVG arc paths) for both the verdict split and the boundary-tie split, horizontal and vertical bar charts (back-test lift, employer count by industry, chance-probability with a drawn 5% threshold line), and a two-series line chart for Roofing's five-year LTC/DI trend. The master-detail shortlist view, the unambiguous/tied split, and the colored flag badges all carried over unchanged from the prior revision, since criteria 2 through 4 were never the problem.

Verified live in-browser, not just read from the diff: all five tabs render and switch correctly with no console errors; the industry and verdict filter dropdowns correctly re-render the shortlist detail panel (tested by driving `industry-filter` to WELDING and confirming the detail header, back-test stats, and the tied-group table all updated to Welding's real deferred-boundary-tie data, five employers tied at score 5, Brownie's Up 5 Welding listed as the representative tied employer); the verdict filter correctly narrows the list panel's count (confirmed "0 of 15" when filtered to Rejected, since 0 industries are rejected, and "15 of 15" back on All); and the Gold Example tab's stat tiles reproduce the pinned CLAUDE.md numbers exactly (1,137 employers, 4,907.7 person-years, 2.71 LTC rate, 4.809 DI rate for 2020) with the five-year trend line rendering alongside them.

## Third revision: a deliberate visual-identity rebuild, not a data change (dated 2026.07.13)
The second revision fixed structure (real tabs, real charts) but kept a generic "BI dashboard template" visual identity, navy sidebar, KPI icon badges, colored pill status tags, blue accent, indistinguishable from a sales-pipeline or marketing dashboard. Requested directly: restyle only, explicitly scoped to exclude the DATA object, verdict logic, and any of the same-day bug fixes (see `evaluation/use-log.md`, 2026-07-13 entry) — a clean separation between correctness work and visual-identity work, done as two distinct passes rather than conflated into one commit.

Rebuilt around a case-file/audit-ledger metaphor grounded in what this data actually is (government case records, verdicts, citations), not a generic template: paper/ink/brass color palette (no blue, no green-as-decoration, only the three verdict colors doing real semantic work); Source Serif 4 for headers (an official-document register) against IBM Plex Sans for body text and IBM Plex Mono reserved specifically for EMP_KEYs, scores, and dates, precision typography applied only where precision is actually being claimed; the left sidebar replaced with literal folder tabs sitting above the content, the active tab's background matching the content panel exactly so it visually "pulls forward" into the page below it; the Gold Example tab moved out of the primary tab row and set apart with a dashed border and an "Appendix — Verification" label, since it is regression evidence, not one of Dana's five decisions; "Back-test & verdicts" relabeled to "Validation" (label only, same underlying content and data). The signature element is the verdict stamp: a rotated (-3deg), double-ringed (border plus offset outline), border-only rubber-stamp treatment in the verdict's ink color, replacing the previous filled pill badges, deliberately the single most visually distinctive thing on the page while everything else (tables, KPI tiles, chart chrome) stays flat and quiet around it, per the brief's own discipline constraint: no gradients, no drop shadows beyond a single hairline border, no rounded corners beyond the stamps themselves, dense unchanged table row spacing (Dana is scanning hundreds of numbers; legibility over atmosphere).

Fonts load from Google Fonts (network-dependent for exact visual fidelity) with real system-font fallbacks declared in the same `font-family` stack (Georgia, Segoe UI, Consolas), so the page remains fully structured and legible with zero network, consistent with this dashboard's standing self-contained-file constraint; only the typographic polish, not the function, depends on network access.

Verified live: computed styles confirmed the folder-tab pull-forward effect (active tab background exactly matches content-panel background), the verdict stamp's actual CSS transform (`matrix(0.99863, -0.052336, 0.052336, 0.99863, 0, 0)`, i.e. -3deg) and double-ring border+outline in the correct ink color, all five tab panels render with content, the Gold Example tab's dashed border, and visible keyboard focus outlines on the new `<button>`-based tab controls. This revision shipped alongside, but strictly after, the same-day verdict-logic fix (`evaluation/use-log.md`), rebuilt from `dashboard_data_v4.json` (10 validated/4 rejected/1 deferred) rather than the pre-fix data, so the restyle was verified against already-correct numbers, not the numbers it was told not to touch.

## Fourth revision: dark palette, quieter stamps, and five new proof/navigation features (dated 2026.07.14)
A single large batch of feature requests landed across several messages, executed as one build (`dashboard_data_v5.json`, `dashboard_template_v5.html`): a dark ink/surface/brass palette replacing the paper palette entirely (`--paper`/`--paper-raised`/`--ink`-as-text renamed and remapped to `--ink`-as-page-bg/`--surface`-as-card-bg/`--text`, since the same variable name meant a different thing in each palette and mixing them up would have been a real, easy-to-miss bug); verdict stamps toned down from a double-ring (border+outline) at -3deg to a single 1px border at -1deg, per direct feedback that the double ring read as "cartoonish clip-art"; the Gold Example tab replaced with a full Verification tab (a 16-option dropdown, Roofing's 2020 pinned anchor plus all 15 confirmed industries' 2024 figures, each compared reported-vs-independently-re-derived with a match/mismatch stamp per field, plus the raw-vs-deduped row count as literal proof of the EMP_KEY dedup step, not just prose); a full-scan sub-view added to Industry Scan (all 114 flagged industries, not just the 15 confirmed, at lightweight scan-level detail); a funnel chart (302→114→15→10) and a lift-vs-population-size scatter chart added to Validation; a province-wide city-clustering card added to Employer Shortlists (aggregated across all 10 validated industries' shortlists combined, distinct from the existing per-industry city column); per-employer dossier drill-down for the top-3 employers of each validated industry (30 total), reusing `employer-briefing`'s actual output shape rather than a summary; one-sentence captions under each tab tying it to the actual question it answers; the industry/verdict filter controls hidden on every tab except Employer Shortlists, the only tab where they do anything; and five new Overview insight elements (a "Findings this cycle" expandable list of the workspace's 11 logged methodology fixes, a flag-reason breakdown, a total-employers-reached stat, a verification pass-rate stat, and a boundary-tie count), the last two computed live from the same `DATA.verification` and `DATA.industries` objects the Verification and Validation tabs themselves use, not hardcoded, so they cannot silently drift out of sync with the tabs they summarize.

**A real performance bug surfaced building the 30 employer dossiers, unrelated to correctness but real enough to fix and log separately**: `ohs_data.py`'s `load_injury()` and `ambiguous_employer_names()` both re-scanned and re-deduplicated/re-grouped the full 841,761-row Injury sheet on every call, timed at 79.7 seconds per repeat `employer-briefing` call even with the workbook itself cached. Fixed by caching both results; repeat calls dropped to 3-5 seconds, with the output values checked identical before and after (342 ambiguous EMP_KEYs, unchanged). This is logged in the git history as its own commit, explicitly separate from the 11 methodology fixes in `evaluation/use-log.md`, since it changes no number any skill produces, only how long producing it takes.

Verified live in-browser (not read from the diff): dark palette confirmed via computed `background-color` at every layer (masthead/tab-bar/content-well/card, no leftover light-mode colors); stamp computed style confirmed a single 1px border, no outline, and a `matrix(0.999848, -0.0174524, ...)` transform (-1deg, not -3deg); the Verification dropdown's default (Roofing) and a second selection (Welding) both rendered correct reported-vs-re-derived values with `match` stamps; the full-scan sub-view rendered all 114 rows; the funnel (4 bars) and scatter (15 points) charts both rendered; a real dossier drill-down opened for a General Trucking employer with actual year-by-year injury/benchmark data; the filter-group's computed `display` was confirmed `none` on Overview and `flex` on Employer Shortlists; and the findings list rendered all 11 entries with the correct first and last item.

## Fifth revision: two outstanding features closed, sticky headers added, then the entire visual direction reversed (dated 2026.07.14)
Three things were flagged as outstanding from the fourth revision and built next: a Data Dictionary appendix tab (static content from `knowledge/data-dictionary.md` and `data-cautions.md`, all 8 sheets plus 6 named cautions, browsable in the same card/table styling as the rest of the dashboard); clickable citations turning every EMP_KEY+year+sheet reference in the Employer Shortlists tables and the Verification tab's sample-row proof into a real raw-row provenance panel (pre-computed and embedded as static data for the 104 distinct employers appearing in any of the 15 industries' shortlists, plus 10 sample raw rows per industry for Verification, no live workbook access in the browser); and a real spec miss caught in a self-audit, the "Findings this cycle" stat had been built as a separate card instead of an actual KPI tile as originally asked, moved into the KPI row as a 6th, clickable tile.

Generating the 104 employers' citation data and the 30 employer dossiers both required a fresh Python process to load the full 841,761-row workbook, a genuinely slow, unavoidable one-time cost (~8-9 minutes) each time; this repeatedly required checking on and waiting for background jobs rather than a quick synchronous build.

The masthead, tab bar, and (Employer-Shortlists-only) filter bar were then made sticky, stacking correctly as three layers with dynamically measured offsets (`updateStickyOffsets()`, computed from actual rendered heights via JS on load and resize, not hardcoded pixel values, since tab captions and flex-wrapping made fixed offsets fragile) and solid backgrounds so scrolling content doesn't bleed through underneath. Verified live specifically on Employer Shortlists (the tallest tab, with all three sticky layers active at once): `.masthead` computed `position: sticky`, `.tab-bar`'s measured `top` offset matched the masthead's real height, and the filter-bar's offset matched masthead+tab-bar combined.

**Then the entire visual direction was reversed**, not iterated on: the case-file/ledger metaphor (paper-then-dark palette, serif headers, folder tabs, rotated ink stamps) was dropped completely in favor of a clean, light analytics-dashboard look matching a reference image (a light `--bg`/`--card`/navy palette, IBM Plex Sans for everything except EMP_KEY/citation text, flat underline tabs replacing folder tabs, rounded pill-shaped toggle buttons replacing `<select>` filters, plain rounded-pill verdict badges with tinted backgrounds replacing the rotated stamps, one navy-filled "headline" KPI tile per section for the single most important number, and a collapsible "How to read this data" cautions section on Overview reusing the same six cautions already curated for the Data Dictionary tab, so the two lists can't drift apart into two different curated sets of the same underlying facts). Executed as a full template rewrite (`dashboard_template_v6.html`) rather than incremental CSS edits, since nearly every rule changed; every existing feature (charts, verification explorer, city clustering, dossier drill-down, data dictionary, citations, sticky headers) was carried over with its logic completely unchanged, only the visual layer rewritten.

Verified live: computed styles confirmed the new palette at every layer (`#EEF1F5` page background, `#FFFFFF` cards, IBM Plex Sans body font with no serif anywhere), the active tab's flat 3px navy underline (no folder-tab border box), the headline KPI tile's solid navy fill with white text, verdict badges as tinted rounded pills with no border or rotation, both pill-toggle groups (4 verdict pills, 15 industry pills) filtering the shortlist correctly on click, the Industry Scan tab's new "15 confirmed" headline stat, the Overview cautions section expanding to show all 6 real cautions, and citations/dossier drill-down/Verification sample-rows/Data Dictionary/funnel/scatter all still rendering correctly with real data after the rewrite.
